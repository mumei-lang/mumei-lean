# Agent guidelines

These rules are for coding agents and harnesses that work in this repository (Devin, Codex, Claude Code, Cursor and others). [`.claude/CLAUDE.md`](.claude/CLAUDE.md) covers the bridge pipeline and Lean build workflow in more detail. The rules below apply in addition to it.

## Fast path

```bash
# Lean toolchain is pinned in lean-toolchain; install with elan, then:
mkdir -p generated/Generated
PATH="$HOME/.elan/bin:$PATH" lake build

PYTHONPATH=scripts MUMEI_LEAN_SKIP_LIVE=1 python -m pytest -q -m "not lake_available"   # offline suite, no toolchain needed
uvx ruff@0.17.6 check                                         # lint baseline (ruff.toml), pinned to match pre-commit/CI
```

Known gotchas:

- `MUMEI_LEAN_SKIP_LIVE=1` does not stop `lake_available`-marked tests; `-m "not lake_available"` is required to skip them (they only need `lake` on PATH). Drop both for the live suite once the toolchain is ready.
- `generated/` is regenerated by bridge runs; keep it out of hand edits and out of diffs.
- Stale-translator gates reject certificates produced by mismatched translator versions/hashes — regenerate rather than editing certs by hand.
- Pre-commit hooks (ruff + hygiene) are configured in `.pre-commit-config.yaml`; `pre-commit install` once.

## Secrets and sensitive data

- Never write a secret value to any output — CLI text, logs, certificates, reports, error messages, test snapshots, PR descriptions or commit messages. Report only whether the secret is set.
- Don't commit credentials; use placeholders in examples and docs.
- Proof certificates and Lean evidence are trust boundaries: never edit certificate verdicts, proof hashes or `z3_check_result` fields by hand — regenerate them.
