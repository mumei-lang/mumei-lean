# Changelog

## 2026-09-19: `task_group:any` lowering as 20th live generated theorem path

- `task_group:any { task { e₁ }; …; task { eₙ } }` now lowers (spec §4.7): the group's value is whichever task finishes first, modelled as list membership over the candidate values — the body lowers to `[e₁, …, eₙ]` (`result_type = "List Int"`), `render_theorem` emits `def <atom>Result … : List Int` with `h_body : result ∈ <atom>Result …` (the `result` binder stays scalar `Int`), and the generated proof is `fin_cases h_body <;> <tactic>`, which substitutes `result := eᵢ` per goal and closes each under `requires`. Every element must be Int-typed; non-Int or partially-lowering siblings keep the group partial — still tagged `concurrency_obligation` for triage, without recording `task_group_any_lowering`.
- Recorded the 20th live generated theorem path `concurrency/task_group_any_winner.mm::race_two_replicas` (`tests/fixtures/concurrency_task_group_any.proof-cert.json`): Z3 `unknown` obligation whose `task_group:any` body previously flagged `unknown_token`, now building `Generated.Concurrency.Task_group_any_winner.race_two_replicas_correct` with `known_witness_used = false`.
- Catalog unchanged: `task_group_any_result_mem` already shipped with the `concurrency_obligation` class, so `bridge_lemma_hash` stays `5716cfdd945d68b4a0d75d75c5ade1934cbd76e0dfe16734a8f3dd723cfdd8e9` and no lockstep bump is needed. Remaining P31 gap: `task_group` segments in the middle of a statement sequence (`read_cancellable_write` shape) still stay partial.

## 2026-09-19: Residual concurrency/ownership surfaces stay partial (self-review follow-up)

- Extended the residual-token coverage beyond `task`/`task_group`: `async`, `await`, `cancel`, `send`, `recv`, `chan`, `acquire`, `consume`, `exclusive`, `shared`, `ref`, `as`, `invariant`, `decreases` are now statement keywords, so surfaces like `{ acquire r { x } }` (real body syntax) or `{ send ch v }` stay partial instead of leaking raw mumei tokens into the emitted Lean. Added a raw-source guard for the channel send/recv arrow and `->`: `ch <- v` tokenises as `<` `-` and would otherwise have been silently reinterpreted as the comparison `ch < -v` — it now flags `channel_arrow_requires_manual_lemma` (legitimate `x < -1` comparisons are unaffected; the check keys on adjacency in the source). Extra enclosing braces around an already-lowered `task`/`task_group` body are now transparent (`{ { task_group:all {…} } }` no longer re-flags the consumed surface), matching the existing `perform`/`let` rule. No obligation-class or catalog change — `bridge_lemma_hash` stays `5716cfdd945d68b4a0d75d75c5ade1934cbd76e0dfe16734a8f3dd723cfdd8e9`.

## 2026-09-18: Structured-concurrency lowering as 19th live generated theorem path (first `concurrency_obligation` class)

- Added lowering rules `task_value_lowering` / `task_group_all_lowering` (`docs/LEAN_TRANSLATOR_SPEC.md` §4.7, §8): a bare `task { e }` evaluates to `e`, and `task_group:all { task {…}; … }` yields the last task's value — sibling tasks' effects are ordering obligations carried by effect metadata, not part of the group value (mirroring §4.3 `perform` handling). Every task item must be a `task {…}` block and every task body must lower cleanly — a partial sibling anywhere keeps the group partial. Task bodies recurse through `translate_body`, so let sequences, nested conditionals, and struct projections compose inside them. Also added: `x = e` rebind segments on `let`-bound names inside statement sequences (`rebind_statement_lowering`), needed by the `per_task_local_writes` shape. `task` / `task_group` are statement keywords, so a residual task surface (`task { a } + x`, an empty `task { }`, `let x = task { 5 }; x`) stays partial instead of leaking raw mumei braces into emitted Lean. `task_group:any {…}` stays partial — its value is list membership over the task results, which needs a different generated theorem shape.
- New obligation class `concurrency_obligation` (spec §10) backed by three new `MumeiLean.Concurrency` bridge lemmas (`task_group_all_result_last`, `task_group_any_result_mem`, `task_value_result`). This is the first catalog change since the `smart_contract_*` extension, so `bridge_lemma_hash` bumped from `ee8cd3ba96c3318b3f07445f4755619744d4e1f9a662af94f3cbce6d41ed4347` to `5716cfdd945d68b4a0d75d75c5ade1934cbd76e0dfe16734a8f3dd723cfdd8e9` — updated in lockstep across `scripts/expr_translator.py`, `scripts/export_cert.py`, `MumeiLean/CertWriter.lean`, all fixture `.proof-cert.json` files, the pinned docs (`LEAN_TRANSLATOR_SPEC` §9, `LEAN_HARNESS_CONTRACT`, `BRIDGE_HARNESS_SPEC`, `INTEGRATION`), `tests/test_lean_bridge_e2e.py`/`test_contract_vocabulary.py`, plus mumei (`mumei-core/src/verification/types.rs`, `tests/fixtures/proof-cert/verified_sample.proof-cert.json`, `docs/PROOF_CERTIFICATE.md`) and mumei-agent (`agent/strategies/foreign_code_strategy_helpers.py`). `translator_version` stays `mumei-lean-translator-ir-v2`.

## 2026-09-18: Nested-`if` lowering as 17th live generated theorem path

- Added lowering rule `nested_if_lowering` (`docs/LEAN_TRANSLATOR_SPEC.md` §4.5, §8): `_parse_braced_if` splits `if c { a } else { b }` by brace depth instead of the previous flat `[^{}]+` regex, so branches may carry nested conditionals and `else if` chains (`{ if x < lo { lo } else { if x > hi { hi } else { x } }` → `if x < lo then lo else if x > hi then hi else x`). ## 2026-09-18: `let` statement-sequence lowering as 16th live generated theorem path

- Added lowering rule `let_statement_lowering` (`docs/LEAN_TRANSLATOR_SPEC.md` §4.4, §8): a brace-enclosed body block whose top-level `;`-separated leading segments are `let <name> = <expr>` (interleavable with `perform` segments, §4.3) followed by a non-empty tail denotes the tail with each binding substituted. Substitution is sequential, so a later binding may reference earlier names (`{ let x = a; let x = x + 1; x }` → `(a + 1)`), and `normalize_body_source` applies the same lowering for result-type inference. Conservative fallbacks keep the block partial: a bound name rebound inside the tail (`let` / `forall` / `exists` binder), a bound name in call position, a trailing `let`/`perform` segment, or `==` in place of `=`.
- Recorded the 16th live generated theorem path `concurrency/linear_ownership.mm::move_once` / `read_before_move` (`tests/fixtures/concurrency_linear_ownership_let_sequence.proof-cert.json`): Z3 `unknown` linear-arithmetic obligations whose `let` sequence bodies previously flagged `unknown_token`, now building `Generated.Concurrency.Linear_ownership.move_once_correct` / `read_before_move_correct` with `known_witness_used = false`.
